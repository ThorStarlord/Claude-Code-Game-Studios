# Adopt Existing Game

1. Confirm the repository and clean working context; identify the engine and its pinned version.
2. Inspect current status/roadmap and the game's existing design, implementation and verification authorities.
3. Resolve source, tests, scenes and assets to paths that actually exist. If ambiguous, report unresolved; never assume `src/` or create a second implementation tree.
4. Identify current playable capabilities, the nearest bounded unfinished responsibility and its dependencies.
5. Compare conventions with CCGS requirements; classify integration gaps without renaming or overwriting canonical game files.
6. Return a short adoption brief: actual layout, verified capabilities, authoritative sources, proposed bounded increment, risk and next task.

Do not generate replacement GDDs, change engine versions, write application code or claim runtime qualification during this read-first workflow.
